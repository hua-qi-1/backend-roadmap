# LeetCode 1. 两数之和（2026-10-18）

题目：给定整数数组 `nums` 和目标值 `target`，找出**两个下标** `i != j` 使 `nums[i] + nums[j] == target`，返回这两个下标。

代码：[`java-se/leetcode/TwoSum.java`](../../java-se/leetcode/TwoSum.java)

## 思路演进

### 暴力枚举（基线）

双重循环枚举所有 `(i, j)` 组合，`j` 从 `i + 1` 开始避免重复和自己配自己。

- 时间 **O(n²)**、空间 **O(1)**
- n = 10⁴ 时约 5×10⁷ 次比较，能 AC，但面试官会追问

### 哈希表（面试答案）

全程只扫一遍：

1. 对当前 `nums[i]`，算出还差多少：`need = target - nums[i]`
2. 查表：`need` 之前见过吗？见过就直接返回 `[seen.get(need), i]`
3. 没见过就记下自己：`seen.put(nums[i], i)`

- 时间 **O(n)**、空间 **O(n)**（用空间换时间）

## 三个必须能答上来的问题

**Q1：HashMap 的 key 和 value 各存什么？**

| | 存什么 | 为什么 |
|---|---|---|
| key | **数值** | 查询方式是「按数值找下标」，所以必须按数值查 |
| value | **下标** | 题目要返回下标；且最终返回的答案是下标 |

反过来（key=下标、value=数值）就无法 `containsKey(need)`，只能退化成 O(n) 的遍历。

**Q2：为什么必须「先查后插」，不能「先插后查」？**

以 `nums = [3, 3], target = 6` 为例：

- 先插后查：`i = 0` 先 `put(3, 0)`，再查 `get(6-3) = get(3)` → 命中**自己**，返回 `[0, 0]`（同一个元素用了两次，非法）
- 先查后插：`i = 0` 表为空，未命中，再插 `(3, 0)`；`i = 1` 查 `get(3)` → 命中下标 0 → 返回 `[0, 1]` ✅

**Q3：数组里有重复数字会不会出错？**

不会。表里永远只存**当前元素之前**的下标，因此不可能匹配到自己；数值重复时 `put` 只会把 key 覆盖成更新的下标，但那一对配对在更早的查询里就已经命中了，不影响结果。

## 边界情况

- `nums.length == 2`：循环跑两次即可（`i < nums.length - 1` 写成 `i < nums.length` 也不会错，只是多一轮空查询）
- 全是负数：`target = -8, nums = [-1,-2,-3,-4,-5]`，`need` 也是负数，哈希表按 `Integer` 处理，没有溢出问题
- 题目保证**恰好一组解**，所以不用处理无解（返回空数组仅作兜底）

## 今日踩的坑（C 语言版）

LeetCode C 的签名是：

```c
int* twoSum(int* nums, int numsSize, int target, int* returnSize)
```

`returnSize` 是**输出参数**，不是答案数组：

- `returnSize[0] = i` 实际等于 `*returnSize = i`，会把「元素个数」改成 i
- `returnSize[1] = j` 是越界写 4 字节，踩坏别人的栈内存

正确写法是 `malloc` 一个长度 2 的数组存下标、`*returnSize = 2`、`return` 这个数组，并在找到后立刻 `return`（否则留下的是**最后一组**答案）。

> 结论：C 没有多返回值，才需要这种「指针当出参」的写法；Java 直接 `return new int[]{i, j}`，从根上没有这个问题。**刷题统一用 Java，省时间且贴合面试。**
